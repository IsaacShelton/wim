WIM REQUIREMENTS
================

Wim is a Vim-like code editor that runs on Node.js. It runs in its own
desktop window, not in a terminal.

This file lists what has been asked for so far. "Decided" notes record choices
made where a request was open to interpretation.


1. Core
-------
1.1  Runs from Node.js as a Node project (`node wim.js`), without native code.
     It was first written in Rust; Rust is no longer a requirement.
     Decided: ported to TypeScript (compiled to plain JavaScript by `npm
     install`), rather than compiling the Rust core to WebAssembly.
1.2  Node opens a native desktop window. Works on macOS and Windows.
     Decided: on macOS, a Cocoa window with a WebKit view, created through
     the built-in `osascript` (JavaScript for Automation). On Windows, an
     Edge app window (Edge ships with Windows; Chrome if Edge is missing),
     since Windows has no built-in way to host a modern web view without
     native code. The editor runs in Node and the window only draws.
1.3  Edits code the way Vim does: Vim modes and Vim motions.
1.4  Opens a file given on the command line: `node wim.js path/to/file`.
     Decided: the file's directory becomes the working directory, so the
     tree, the file pickers (`,a`, `,fw`) and relative paths start there,
     as with a directory argument (1.5).
1.5  Given a directory (`wim .`), Wim works in that directory and starts
     with no file open; Ctrl+n shows the tree to open files from.
     Decided: the directory becomes the working directory, so the tree and
     relative paths start there. "No file open" is one empty, unnamed
     buffer, as when Wim starts with no argument.


2. Vim editing
--------------
2.1  Modes: Normal, Insert, Replace, Visual, Visual Line, and the `:`, `/`
     and `?` command lines.
2.2  Motions, operators, text objects, counts, registers, marks, undo/redo
     and search behave as in Vim.
2.3  `.` repeats the last change, and repeats again each time it is pressed:
     after `dd`, each further `.` deletes another line.
     Decided: `u`, `<C-r>` and `.` itself are never recorded as the change
     to repeat.
2.4  Line numbers are relative, with the absolute number on the cursor line
     (Vim's `number` + `relativenumber`). This is the default.
2.5  Yanked text flashes briefly.
2.6  Autopairs: closing brackets and quotes are typed with opening ones.
     Decided: as nvim-autopairs with the Neovim config (its default rules
     without the `'` rule, and `()` added after confirming a function or
     method completion). Its fast wrap (Alt+e) is left out. The
     `autopairs` option (`:set noautopairs`) turns it off, standing in
     for the config's enable/disable functions.
2.7  `<C-d>` and `<C-u>` move the cursor half a page without scrolling,
     unless the cursor would come too close to (or past) the first or
     last visible line.
     Decided: the view then scrolls only as far as `scrolloff` needs.
2.8  `<C-o>` goes back from a jump (such as going to a definition), as in
     Neovim, and `<C-i>` forward.
     Decided: a jump list as in Vim, across buffers (reopening closed
     files). `<C-y>` also goes forward, as mapped in the Neovim config.
2.9  `,w` and `,b`, like `w` and `b` for subwords, as in the Neovim config.
     Decided: `,e` and `,ge` too, as the config maps all four (to
     nvim-spider), in Normal and Visual mode and after an operator
     (`d,w`). Subwords follow nvim-spider's defaults: camelCase humps,
     snake_case parts, ALLCAPS runs and digit runs; a single punctuation
     character is skipped, two or more (`=>`, `::`) are a stop.


3. Buffers
----------
3.1  Several files can be open at once, each in its own buffer with its own
     cursor, undo history and marks.
3.2  Tab and Shift+Tab cycle to the next and previous buffer.
3.3  Open buffers are shown along the top of the window when there is more
     than one.
3.4  `,x` and `:q` on a buffer with unsaved changes ask y/n rather than
     refusing (asked for later).
     Decided: `Discard changes to "name"? (y/n)` on the command line, for
     `:q` (also on the last buffer, before quitting) and `:bd` (which `,x`
     maps to). `y` closes it; `n` or Esc keeps it; any other key keeps it
     and does what it does, so typing `:q!` still works. `:qa` and closing
     the window are unchanged.


4. File tree
------------
4.1  A sidebar file tree shows the project's files.
4.2  Ctrl+n shows and hides it.
     Decided: Ctrl+n works in Normal mode (and in the tree), as in the
     user's Neovim config.
4.3  The tree shows icons for folders and files.
     Decided: icons, folder glyphs and tree settings follow the user's
     Neovim setup (nvim-web-devicons, ~/.config/nvim/lua/dev_icons.lua and
     the nvim-tree options in ~/.config/nvim/init.lua). Icons come from an
     installed Nerd Font.
4.4  `a` in the tree creates a file.
     Decided: as in nvim-tree, the prompt starts with the selected folder
     (or the selected file's folder), relative to the tree's root; a
     trailing `/` makes a folder, missing folders are made, and the new
     entry is selected while the tree keeps focus.
4.5  `dd` in the tree deletes a file, after a y/n question (asked for
     later).
     Decided: the question is on the command line; `y` deletes, `n` or Esc
     keeps it. A folder is deleted with everything in it, and the question
     says so. Buffers of a deleted file stay open.
4.6  Names in the tree are colored by git status (asked for later).
     Decided: untracked, staged, modified (or deleted inside a folder) and
     conflicted each have a color from the theme; a folder shows the
     strongest status inside it (conflicted, then modified, staged,
     untracked). As the open file's color may now be its status, its name
     is also bold. Status is read when the tree is shown, after writes and
     agent edits, on leaving the terminal or agents panel, and with `R`.


5. Windows and key bindings
---------------------------
5.1  Ctrl+h and Ctrl+l (and the other Ctrl+h/j/k/l keys) move between
     windows, e.g. between the file tree and the editor (and split
     windows, 13).
5.2  Key bindings follow the user's Neovim 0.10.4 configuration in
     ~/.config/nvim wherever Wim has the feature they use.
     Decided: mappings for plugins Wim doesn't have (gitsigns, Rust
     auto-import) are left out. Telescope's pickers become Wim's own
     picker (see 7 and 8), nvim-spider's motions Wim's own (2.9), and the
     theme toggle switches Wim's themes (12).


6. macOS text editing in Insert mode
------------------------------------
6.1  Option+Left and Option+Right move by word.
6.2  Option+Delete and Option+Backspace delete a word, as in standard macOS
     text editing.
     Decided: Option+Delete (the ⌫ key) deletes the word before the cursor;
     Option+fn+Delete (⌦) deletes the word after it.
     Decided: on Windows, Alt stands in for Option, both for these keys and
     for the Option mappings in 5.2; Cmd shortcuts are Ctrl+Shift there.


7. Language servers
-------------------
7.1  LSP support for Rust, TypeScript (and JavaScript) and Python.
     Decided: rust-analyzer, typescript-language-server and pylsp (with
     the Neovim config's pycodestyle settings), found in Neovim's Mason
     directory first, then on the PATH, since that is how the user's
     Neovim finds them. A project's own copy comes before both
     (node_modules/.bin; for pylsp, the virtual environment's: .venv,
     venv or $VIRTUAL_ENV), and pylsp can also run as `python -m pylsp`.
     Decided: a project's virtual environment is preferred for pylsp, so
     it sees the project's packages: its pylsp, else its Python with
     `-m pylsp`, before Mason's; a pylsp from elsewhere gets Jedi's
     `environment` set to the virtual environment's Python. A command that fails to start (such as a rustup
     proxy with no rust-analyzer installed, or a Mason install built for
     another CPU) falls through to the next one found; when none start,
     the message says why each one failed.
     Decided: features and mappings follow the Neovim config's LspAttach
     mappings, diagnostic settings, nvim-cmp and conform.nvim setup:
     diagnostics (underline, virtual text, signs, update in Insert mode),
     completion, hover (`K`), go to definition/declaration/implementation/
     type definition, references, rename, code actions, document and
     workspace symbols, formatting (`,f` and on save), diagnostic jumps and
     lists, and highlighting other uses of the symbol under the cursor.
     Decided: the sign column is shown for files a language server handles
     (`signcolumn=yes` there), and not for other files.
     Decided: completion items are inserted as plain text (the client does
     not advertise snippet support), since Wim has no snippet tab stops to
     jump between.
     Decided: formatting on save happens after the write: the formatted
     text is written again if the buffer hasn't changed meanwhile.
     Decided: `<C-Space>` with no completion menu open asks for
     completions.


8. Finding files and text
-------------------------
8.1  `,a` finds files and `,fw` searches text, as Telescope's find_files
     and live_grep do in the Neovim config.
     Decided: both use ripgrep with the Neovim config's
     `vimgrep_arguments`, and leave out `node_modules` (its
     `file_ignore_patterns`). Without ripgrep, files come from git (or a
     directory walk) and are searched with JavaScript regular expressions,
     so they also work where ripgrep isn't installed (such as a plain
     Windows machine).
     Decided: pickers use Telescope's horizontal layout from the config
     (97% by 90% of the window, prompt on top, a preview of the selected
     item's file beside the results when the window is at least 120
     columns wide). The LSP pickers that list locations get the preview
     too.
     Decided: live grep stops after 5000 matches.


9. Images
---------
9.1  Images (PNG, JPEG and WebP) can be viewed.
     Decided: GIF and BMP too. An image file opens in a buffer that shows
     the image centered and shrunk to fit (never enlarged), with its
     format, size and file size in the status line; pickers preview
     images as well. Image buffers can't be changed or written, so
     writing can never replace an image with text. The window loads
     images from Wim's local server, which serves only image files and
     only with the session's token.
9.2  Images can be zoomed and moved, with the mouse and with `+`, `-`
     and `=`: scrolling zooms, dragging pans, and three small buttons in
     the buffer's bottom right corner do `+`, `-` and `=`.
     Decided: the `=` key zooms in like `+` (asked for later); the `=`
     button, and the `0` key, fit the window again. `-` zooms out. Keys
     and buttons glide to the new zoom or place over a few frames (and a
     clicked button looks pressed for a moment); the mouse moves it
     directly. Scrolling and trackpad
     pinching zoom around the pointer. Dragging, `h`/`j`/`k`/`l` and the
     arrows move the image at any zoom; the middle of the window stays
     over the image. Each step is 25%. Pixels are drawn sharp from 200%.
     Zoom is kept per buffer.
9.3  Small images start zoomed in when opened.
     Decided: an image that would fit two or more times its size opens
     (and fits again with `0` or the `=` button) at the most whole times
     that fit, which keeps its pixels sharp.


10. Signature help
------------------
10.1 Signature help while typing.
     Decided: a float above the line (below it when the completion menu
     is above) opens on the server's trigger characters (`(` and `,`
     usually, including the `()` added after a completion) and follows
     the typing: the current parameter is highlighted and its
     documentation shown. It closes when the server says the cursor is
     no longer in a call, on leaving Insert mode, or on moving to
     another line.


11. Sounds
----------
11.1 Music files can be played, as images are shown: with play/pause, a
     scrubber, volume and so on.
     Decided: MP3, WAV, FLAC, Ogg, Opus, AAC and WebM audio open in a
     read-only buffer showing a player that Wim draws: name, format, size
     and length, play/pause, a scrubber with times, and volume (with
     mute), all clickable, plus keys (Space/Enter/p, h/l and arrows to
     seek, 0-9 to jump, k/j and arrows for volume, m to mute). The window
     plays the sound with an <audio> element from Wim's local server
     (which now serves byte ranges, as players need). One sound plays at
     a time; it keeps playing in other buffers, shown in the status line,
     and stops when its buffer is closed. Sounds don't start on opening.


12. Themes
----------
12.1 Switch between the current colors and Nord, as in the Neovim config.
     Decided: `,th` (the config's toggle, there between Nord and ayu-light)
     and `:colorscheme nord` / `:colorscheme onedark`. Nord's colors come
     from nord.nvim with the config's options, and the mode colors from
     lualine's Nord theme. Search matches use a darker ice than the
     config's reversed ice, since Wim draws them behind the text. One Dark
     stays the default, and the choice isn't saved between sessions.
12.2 Highlighting in Nord matches Neovim's (tree-sitter and LSP semantic
     tokens with nord.nvim).
     Decided: Wim's syntax highlighter sorts code into tree-sitter's kinds
     of token, each with its nord.nvim color, and semantic tokens from the
     language server are laid over it, mapped as nord.nvim maps
     `@lsp.type.*` (types it leaves alone, such as variables and structs,
     keep their syntax color). Checked against a screenshot of Neovim:
     the colors of about 40 sampled tokens of each kind match. Comments are italic in Nord (the
     config's `styles.comments`). One Dark looks as before.


13. Split windows
-----------------
13.1 Horizontal and vertical splits.
     Decided: as in Vim: `:split`/`:vsplit` (with an optional file),
     `:new`/`:vnew`, `:only`, `:close`, and <C-w> s v n c q o w W p h j k l.
     New windows go above or left and become active; windows share their
     space evenly (no resizing); each has a name bar and its own cursor
     and scroll position. `:q` closes a window before a buffer. Ctrl+h/j/k/l
     move between windows, reaching the file tree on the left. Clicking a
     window focuses it; scrolling over one scrolls it. Closing a buffer
     closes the windows showing it.


14. Claude Code
---------------
14.1 An agent chat window, toggled from the right-hand side, that connects
     to Claude Code: it manages several Claude Code sessions, shows their
     context, and has chatting, scrolling through history, and control of
     permissions and the model.
     Decided: a panel on the right of the window, toggled with Cmd+L
     (Ctrl+Shift+L on Windows and Linux, as Wim's other Cmd shortcuts), `,cc`
     (unused in the Neovim config) and `:Agents [message]`, and by clicking
     a `✻ Agents` badge at the right end of the status line, which also
     shows when a session is working or waiting for an answer. Ctrl+h and
     Ctrl+l move between it and the editor, as with the file tree.
     Decided: sessions run through the Claude Agent SDK (the
     @anthropic-ai/claude-agent-sdk package, which bundles Claude Code), with
     Claude Code's system prompt, tools and settings as in the terminal, in
     Wim's working directory. A session's process starts with its first
     message, so opening the panel costs nothing; one that stops starts
     again, resuming the session, with the next message.
     Decided: sessions are tabs in the panel; `s` lists the open ones and
     those Claude Code saved for the directory (from Wim or the terminal),
     to resume with their history.
     Decided: the panel has a Normal mode (reading and scrolling, single
     keys for sessions and settings, `?` lists them) and the prompt (`i`),
     like Vim's modes; Esc leaves the prompt. Mappings don't apply in the
     panel. Ctrl+c is Esc, as in the editor (asked for later); Ctrl+x
     interrupts Claude, from either mode.
     Decided: "context" is the session's context use (percentage, and by
     kind with `c`, as `/context` shows it) and cost. Model, permission mode
     and effort come from pickers. Shift+Tab goes to the previous session,
     as Tab goes to the next (asked for later; not the terminal's mode cycle).
     The bypass-permissions mode is offered (it is never the default).
     Decided: permission prompts and AskUserQuestion are answered in the
     panel, as in the terminal: Yes, Yes and don't ask again (Claude Code's
     suggested rule), No (which stops the turn) and No with what to do
     instead. Prompts Claude Code marks as risky start on No and can't be
     approved with one key.
14.2 Files Claude changes stay in step with Wim.
     Decided: a buffer of a file Claude edited (or, after a shell command,
     any whose file changed) is reloaded as one undoable change, as Vim's
     `autoread` would; a buffer with unsaved changes is kept, with a warning
     when Claude edited its file.
14.3 The panel says "agents" rather than "Claude" (asked for later).
     Decided: its name, badge (`✻ Agents`), mode pill (AGENT), messages
     and the `:Agents` command; the README still says the agents are Claude
     Code sessions. Titles Claude Code itself gives a permission prompt
     ("Claude wants to…") are shown as it sends them.
14.4 Ctrl+h and Ctrl+l move between windows, even from the agents panel's
     prompt.
     Decided: in the panel's prompt they move between the panel and the
     editor, as in its Normal mode, rather than the cursor; the editor's
     Insert mode keeps the Neovim config's Ctrl+h/l cursor keys.
14.5 Claude Code is only used when the settings turn it on.
     Decided: `claude.enabled` in `wim.config.json`, false by default. With
     it off, Cmd+L, `,cc` and `:Agents` say so, and the status line has no
     badge.
14.6 Presets for low, medium and high complexity tasks, each a model and
     effort set in the settings (by default Haiku 5.5 at low effort, Sonnet
     5.5 at medium and Opus 5.5 at high), selected in the agents panel.
     Decided: `L`, `M`, `H` in Normal mode, `P` to pick, or a click on the
     preset in the header. A preset applies to the next request, also while
     a session is working; picking a model or effort by hand leaves the
     preset. `claude.defaultPreset` is what new sessions start with.
14.9 The default agent uses the high preset (asked for later).
     Decided: `claude.defaultPreset` is `high` by default (and set in
     wim.config.json); `null` keeps Claude Code's own settings, as unset
     did before.
14.7 The panel's top shows context use and whether the prompt cache is
     stale.
     Decided: a second row under the model, mode and effort: a meter and
     percentage for context use, and the time left in the cache, "cache
     cold" in red once it has run out. Claude Code does not report the
     cache, so it is estimated as `claude.cacheMinutes` (60) after the last
     reply.
14.8 A way to see the plan's usage limits.
     Decided: the plan limit closest to running out (5-hour or weekly) is
     in the second row, and `u` or a click shows all of them with when they
     reset, from the Agent SDK's experimental usage request (the data
     behind `/usage`). They exist for Claude subscriptions only.


15. Settings
------------
15.1 A small configuration file in Wim's root directory for settings.
     Decided: `wim.config.json` (JSON, as it needs no parser of its own).
     It holds the theme (`onedark` or `nord`, default `onedark`), whether
     Claude Code is enabled (14.5), the presets (14.6), the prompt cache
     length (14.7) and the terminal's shell (16.1). Missing keys use the
     defaults; mistakes are reported at startup and ignored.


16. Terminal
------------
16.1 An integrated terminal: zsh on macOS, PowerShell on Windows.
     Decided: it sits under the editor (Cmd+J, `,tt`, `:Terminal`).
16.2 The terminal is a real tty (asked for later).
     Decided: the shell runs on a pseudo-terminal made by the system's
     `script` command (behind `cat`, as macOS's `script` refuses a socket
     for input), so Wim still has no native code; @xterm/headless, plain
     JavaScript, emulates the terminal, and Wim paints its screen with the
     theme's 16 colors (and 256 and true colors). The shell is an
     interactive login shell, so ~/.zshrc applies. The pseudo-terminal is
     resized with `stty` from outside, which tells the program (SIGWINCH).
     Keys go to the program as xterm sends them, except Ctrl+h/j/k/l, which
     move between windows (5.1, 14.4); Esc goes to the program. The wheel
     and PageUp/PageDown scroll back, except in full-screen programs. When
     the shell exits, Enter starts another. Where there is no `script`
     (Windows), the earlier line-based terminal stays: commands typed in
     Wim's prompt, output as plain text. The Linux (util-linux `script`)
     and Windows setups have not been tried.


17. Bundled font
----------------
17.1 The Nerd Font in use is part of the repo, so it needn't be installed.
     Decided: FiraMono Nerd Font Mono Regular, in `fonts/` with its SIL OFL
     license; an installed Nerd Font is only used if `fonts/` has none.


18. Markdown
------------
18.1 Links between Markdown files can be followed, as in Obsidian.
     Decided: the working directory is the vault. Wikilinks (`[[note]]`,
     `[[note#heading]]`, `[[note#^block]]`, `[[note|text]]`,
     `[[#heading]]`) and Markdown links (`[text](note.md#heading)`, with
     `%20` and the like decoded) are followed with `gf` or Enter on them
     (as obsidian.nvim maps them) and with Cmd+click (Ctrl+click on Windows
     and Linux), as Obsidian's editor does. Enter not on a link moves down
     as usual; `gf` not on a link opens the file named under the cursor, as
     in Vim.
     Decided: a name is looked for beside the current note, then from the
     vault's top, then anywhere in the vault by the end of its path, the
     nearest to the current note first (hidden folders and `node_modules`
     are left out). A name without an extension is a `.md` note. A note
     that doesn't exist opens as a new buffer beside the current one, and
     is made when written. A heading matches by its text (ignoring case
     and markup) or by its GitHub-style slug; a block by the `^id` ending
     its line.
     Decided: following a link is a jump, so `<C-o>` comes back. Web links
     (`http:`, `https:`, `mailto:`) open in the default browser; other
     schemes aren't opened.
18.2 Links are clickable in the rendered view (`,m`).
     Decided: a click follows a link; a Markdown note opens rendered too.
     `<C-o>` and `<C-i>` work in the rendered view, and come back to the
     place being read. Wikilinks show their text, or `note > heading`.
18.3 Images in Markdown files can be viewed.
     Decided: in the rendered view, a line of only images (`![alt](src)`,
     `![[file]]`) shows them, from Wim's server as image buffers are;
     Obsidian's `|300` or `|300x200` sets the size. They are shrunk to fit
     the width and the window's height, and a click opens the image. Images
     inside text, missing ones and web images stay as their names (web
     images aren't fetched).
18.4 Mermaid diagrams are shown in the rendered view.
     Decided: drawn in the window by Mermaid (the `mermaid` npm package, so
     Wim stays without native code; its script is served by Wim's server
     and loaded the first time a diagram is shown), with theme variables
     from Wim's colors. The window says how big each diagram is, so Node
     lays out rows for it; all diagrams in a file are drawn as soon as it
     is shown rendered, so the view doesn't move when scrolling to one.
     Labels are SVG text rather than HTML, as HTML inside an SVG drawn as
     an image doesn't show in every engine. A diagram Mermaid can't read
     shows its error and source.
